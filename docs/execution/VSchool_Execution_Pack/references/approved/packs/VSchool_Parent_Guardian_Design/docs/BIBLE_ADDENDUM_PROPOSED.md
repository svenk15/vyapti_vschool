# Proposed Bible addendum — Parent & Guardian workspace

Append only after reconciliation with the current Bible. This document does not overwrite approved decisions, task states or release gates.

The Parent & Guardian workspace begins in Phase 2 on top of Phase 1 school identity, student/enrollment and attendance foundations. The school verifies each institution/child/adult relationship and intended purpose before activation. Account, guardian, payer, pickup, emergency contact and consent signer remain separate authorities. One account can hold independently scoped child links across branches and institutions.

The selected child defines the active school/branch context. Every read, mutation, document and delivery rechecks its current purpose grant. Module visibility additionally requires release, institution entitlement and branch enablement. Parent access never follows solely from an email match, household label or school role.

Phase 2 covers verified access, family home, session attendance, explanation/query, notices/replies, basic calendar, requests and own-account support. Phase 3 adds learning, documents/consent and applicant workflows. Phase 4 exposes published results. Phase 5 adds explicit payer workflows and verified payment outcomes. Phase 6 services remain independently scoped. Phase 7 provides reviewed evidence-based explanations without autonomous consequential actions.

An absence explanation is not a correction; a request is not approval; an acknowledgement is not consent; a single signer response may not complete permission; a payment attempt is not settlement. UI and domain state names preserve these distinctions.

All personas reuse the approved theme and component system. Parent navigation is simpler and mobile-first, with persistent child identity and clear school source. The full design pack contains proposed extensions for meetings, events, pickup, activities and meals that require separate scope/LLD approval.
