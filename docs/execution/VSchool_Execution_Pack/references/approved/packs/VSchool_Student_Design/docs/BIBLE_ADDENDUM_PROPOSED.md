# Proposed Bible append — Student Workspace
Status: design proposal. Append only after reconciling current Bible/ADRs and approved delivery scope; preserve existing text/history.

1. Student workspace composes Access, Students, Academics, Learning, Attendance, Communication, Requests, Assessments and optional Services; it does not duplicate their aggregates.
2. Student authority is a verified institution-local account binding plus active enrollment and current object capability. Parent/guardian identity never implies student submission authority.
3. Phase 2 persona extension covers access, self attendance, messages/requests; full Learning workspace follows Phase 3 owners; published results Phase 4; no default student finance in Phase 5; independent services Phase 6; reviewed AI Phase 7.
4. Published assignment, private draft, ready file, immutable submission, returned feedback and published grade are separate states.
5. Stable intent, versioned review and authorized status reconciliation prevent duplicate accepted work; file assets require trusted clean verdict and immutable bytes.
6. Reuse shared shell, semantic tokens, mobile records, fluid filters, separate Sort drawer, explicit outcomes and distinct sign-out area.
7. Extend one fictional, idempotent demo seed command as each feature ships. Keep production readiness, TEN-03 and native accessibility gates explicit.
8. Link this appendix to module-specific DESIGN.md, TASKS.md and CURRENT_STATE.md; state remains proposed until actual repository evidence is recorded.
