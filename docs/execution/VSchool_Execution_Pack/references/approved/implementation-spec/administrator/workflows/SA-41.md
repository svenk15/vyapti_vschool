# SA-41 — Build and publish a timetable

Owner area: planning. Reference entry: `#/flow/SA-41`. Historical design phase: 3; phase is not current implementation status.

## Authority and outcome

Capability described by catalog: timetable.manage

Outcome: A published timetable version drives idempotent future session generation.

Invariant: Existing open/submitted attendance stays pinned; recurring plan is not the Phase 1 manual-session contract.

Recovery: Clash races and repeated generation cannot produce double sessions.

Data ownership: Academics owns TimetableVersion/slots, room and teacher constraints; Attendance consumes versioned generation commands.
