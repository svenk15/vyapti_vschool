# SA-18 — Register a student manually

Owner area: students. Reference entry: `#/flow/SA-18`. Historical design phase: 1; phase is not current implementation status.

## Authority and outcome

Capability described by catalog: student.manage

Outcome: A Student profile references the deliberately selected organization Person.

Invariant: Same-institution identity lookup is exact admission number or person ID only; no broad person discovery.

Recovery: Duplicate/racing admission numbers show the existing permitted record or a conflict; no automatic merge.

Data ownership: People Person and Students Student are created through the owner contracts in the documented transaction.

## Exact catalog steps and fields

### Step 1: Identity

Create a person or explicitly select an exact existing identity.

| Key | Label | Control | Required | Options |
|---|---|---|---|---|
| match | Identity selection | select | True | ["Create new Person", "Exact person ID", "Exact admission number"] |
| lookup | Exact reference if selecting existing | text | False | [] |
| first | First name | text | True | [] |
| last | Last name | text | False | [] |

### Step 2: School record

Admission number stays stable in this branch.

| Key | Label | Control | Required | Options |
|---|---|---|---|---|
| admission | Admission number | text | True | [] |
| joined | Admission date | date | True | [] |

### Step 3: Review identity

Review a single exact candidate; do not match by email, name similarity or ranked results.

| Key | Label | Control | Required | Options |
|---|---|---|---|---|
| identity | I have verified that this is the intended student. | checkbox | True | [] |
