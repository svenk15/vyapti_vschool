# Administrator → Staff mandatory-flow audit

## Classification rules

- **MANDATORY**: required by the current Staff directory or SA-13–SA-17 contract for a usable, safe Staff lifecycle.
- **CONDITIONAL**: required only when the relevant module, explicit designation or exact operational situation applies.
- **DEFERRED**: explicitly outside the current Staff release; it is not counted as a defect in an otherwise supported current-release flow.

Implementation status uses only the requested values. `IMPLEMENTED_AND_VERIFIED` means current code has focused functional/security evidence for the stated bounded outcome. It does not mean human acceptance or production readiness. `PARTIAL` means a supported subset exists. `BLOCKED_BY_CONTRACT` means the necessary owner command or lifecycle contract is absent; this audit does not invent it.

## Confirmed implementation facts

1. **Identity boundaries are sound in the supported paths.** Staff creation never treats email/name equality as a merge. Employee access requires exact Employee selection, a non-sensitive independent verification reference and an Access-owned atomic grant.
2. **Employment, access, Teacher eligibility and assignment are separate aggregates.** Current UI labels them separately. Category is descriptive and grants no capability.
3. **Server authorization is independent of navigation.** People queries/mutations, Access grants/membership changes, availability and cover all recheck live identity, membership, module and resource requirements. Hiding a link is not relied on as authorization.
4. **Current operational availability is privacy-minimized.** Principal projection excludes the source reference and private narratives; missing evidence is `UNKNOWN`, never assumed available.
5. **The most serious recovery defect is presentation-level.** Several owners already have exact receipts/CAS, but create/manage screens do not consistently preserve keys or distinguish a committed mutation from a failed read refresh.

## Connected Administrator → Staff recipient walkthrough

This uses fictional data and existing supported operations only.

1. Sign in as the seeded School administrator and open **Staff → Profiles** (`/admin/teachers`). Search by the fictional name or Employee code. Observe separate Employment, Access and Teaching states.
2. Choose **Add staff**, enter a new fictional Person/Employee, review Employment, and confirm. A receipt must link back to Staff and offer **Grant sign-in access**. This path always creates a new Person; do not use it for an already-established Person.
3. Open **Grant sign-in access**, select the exact new Employee, record a non-sensitive synthetic verification reference, choose an allowed branch role, confirm and submit. For email modes, expect a pending membership plus an honest sent/failed delivery state. For operator mode, expect no email invitation.
4. In the local development mail sink only, open the fictional invitation as a separate browser context and accept it using the intended account. Do not use a real recipient or print the token.
5. Return as administrator to **Staff → Access**. Review the membership, suspend it with a reason, then make a protected request in the recipient context. The next request must be denied. Reinstate only an eligible membership and verify access returns.
6. If the account is a verified active teaching Employee, enable current Teacher eligibility and use **Academics → Classes and teachers** to create a dated assignment. The Staff page does not yet show that assignment history.
7. If the administrator has the explicit availability-recorder designation, open **Staff availability** and record a bounded fictional interval. The Principal sees only safe state/time. A cover coordinator may use the existing exact-occurrence flow; general leave approval is unavailable.

## Mandatory gaps versus deliberate exclusions

- **Mandatory implementation gaps:** URL-backed directory controls; exact existing-Person linkage; authoritative profile/corrections; dated Teacher eligibility; Staff-context responsibilities/history; reasoned invitation review; complete employment lifecycle; integrated mutation recovery.
- **Conditional implemented capabilities:** operational availability and exact-occurrence cover.
- **Explicitly deferred:** advanced leave/coverage policy (SA-53), payroll/contract/qualification HR, real provider delivery, and production tenant enforcement.
- **Release gates unchanged:** TEN-03, production email/provider review, native VoiceOver/NVDA, font portability where recorded, and human visual acceptance.
